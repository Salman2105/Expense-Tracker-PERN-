# PHASE 15 — FINAL FRONTEND CLEANUP & PRODUCTION READINESS

You are working on my existing **Expense Tracker PERN frontend**.

Tech stack:

* React 19
* TypeScript
* Vite
* React Router
* Axios
* TanStack React Query
* Tailwind CSS
* Backend: Express + PostgreSQL + Prisma
* Authentication: JWT
* Frontend architecture is feature-based

## IMPORTANT RULES

1. **Inspect the entire existing frontend before making changes.**
2. Do NOT rebuild the frontend from scratch.
3. Do NOT introduce new features.
4. Do NOT change working backend APIs or API contracts.
5. Preserve the existing UI/design/theme.
6. Preserve the existing authentication/session architecture.
7. Preserve the existing React Query architecture.
8. Reuse existing utilities/types/components instead of creating duplicates.
9. Do not use `any` to hide TypeScript problems.
10. Do not remove code/dependencies/types unless you verify they are unused.
11. Keep `src/api/client.ts` as the canonical Axios/API client.
12. Do not create another API client.
13. Keep the existing feature-based architecture.
14. Make production-safe changes only.
15. After each major cleanup, verify that imports and references remain valid.
16. Do not make unnecessary refactors just for stylistic preference.

# 15.12 FINAL FRONTEND ARCHITECTURE REVIEW

Perform a final architectural audit.

The architecture should conceptually remain:

```text
                    React Application
                           │
              ┌────────────┴────────────┐
              │                         │
           Routing                  AuthProvider
              │                         │
              └────────────┬────────────┘
                           │
                     Feature Pages
                           │
                     React Query
                           │
                    Feature Services
                           │
                     API Client
                           │
                         Axios
                           │
                      Backend API
```

Confirm:

### Authentication

* AuthProvider owns auth state.
* Token/session handling is centralized.
* Axios attaches the token centrally.
* 401 handling is coordinated with the auth/session layer.
* Logout cleans up frontend session state.

### Server state

* React Query handles server state.
* Queries are centralized through feature hooks/services.
* Mutations invalidate appropriate queries.
* No unnecessary manual server-state management exists.

### API

* One canonical Axios client.
* Feature services encapsulate API calls.
* Components do not directly call Axios.

### Routing

* Public/protected routes are correctly separated.
* Auth initialization is handled.
* Redirect behavior is consistent.

### Components

* Feature components remain feature-specific.
* Shared components are genuinely reusable.
* No unnecessary duplication.

### Types

* Domain models are reused.
* API contracts are explicit.
* No unnecessary duplicate types.
* No `any` used to hide errors.

### Configuration

* Environment variables are correct.
* No secrets are exposed.
* API base URL configuration is centralized.

### Code quality

* TypeScript passes.
* ESLint passes.
* Production build passes.
* No obvious dead code remains.
* No unnecessary dependencies remain.
