TASK: Replace Profile Picture URL Input with Cloudinary Image Upload

Project:
This is my existing Expense Tracker PERN application.

Stack:
- Frontend: React 19 + TypeScript + Vite + React Router + Tailwind CSS
- Backend: Node.js + Express
- Database: PostgreSQL + Prisma
- Authentication: JWT
- Existing User/Profile Management API
- Existing User model already has an optional profilePicture field
- Cloudinary should be used as the image storage provider.
- PostgreSQL should store ONLY the Cloudinary image URL.

IMPORTANT:
Do not redesign or rewrite unrelated parts of the application.
Do not create a second profile system.
Do not duplicate existing API clients, services, types, or authentication logic.
First inspect the existing frontend and backend architecture and reuse the existing patterns.

CURRENT PROBLEM:
The Edit Profile modal currently contains:

"Profile picture URL"

with a text input where the user manually enters something like:

https://example.com/photo.jpg

This is not the desired UX.

REPLACE THIS WITH:
A proper profile-picture upload interface where the user can:

1. Click an upload/select-image area.
2. Select an image from their device.
3. See a preview of the selected image.
4. Upload the image through the application backend to Cloudinary.
5. Receive the Cloudinary secure URL.
6. Save ONLY that URL in the user's profilePicture database field.
7. Display the uploaded profile picture in the profile UI/navbar wherever the existing profile picture is used.

==================================================
ARCHITECTURE
==================================================

Implement this flow:

Frontend
    ↓
Select image
    ↓
Validate image
    ↓
Preview image
    ↓
Send multipart/form-data to backend
    ↓
Backend authentication/authorization
    ↓
Backend uploads image to Cloudinary
    ↓
Cloudinary returns secure_url
    ↓
Backend saves secure_url in PostgreSQL
    ↓
Backend returns updated user/profile
    ↓
Frontend updates Auth/Profile state

The frontend must NOT directly write anything to PostgreSQL.

The frontend should preferably NOT communicate directly with Cloudinary unless the existing architecture specifically requires it. Keep Cloudinary credentials/configuration on the backend.
